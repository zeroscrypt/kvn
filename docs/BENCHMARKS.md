# Бенчмарки KVN

Документ фиксирует измеренные характеристики KVN: микробенчмарки ядра,
размеры фронтенда и поведение десктопного приложения при старте, в idle и
при завершении. Все цифры получены реальными прогонами на релизной
сборке; всё, что не измерялось, перечислено явно в разделе
«Что не измерено».

## Методология и стенд

| Параметр | Значение |
|---|---|
| ОС | macOS 26.7.1 |
| Архитектура | arm64 (Apple Silicon) |
| Профиль сборки | release (`pnpm tauri build`, фронтенд встроен) |
| Дата измерений | 16 октября 2026 |

Принципы:

- Все замеры воспроизводимы точными командами из раздела
  «Как воспроизвести» — никаких «оценочных» чисел.
- Микробенчмарки — одиночный прогон после warm-up (`std::hint::black_box`,
  `std::time::Instant`); десктопные замеры — медиана по трём прогонам.
- Цифры времени зависят от железа и фоновой нагрузки: на другой машине
  они будут иными, важна методика, а не абсолют.
- Самый первый запуск нового бинарника в сессии занимает заметно больше
  (кеши ОС ещё холодные) — в одной из сессий это наблюдение составило
  ~3 с; таблицы ниже отражают прогретые прогоны.

## Микробенчмарки ядра (kvn-core)

Команда:

```
cargo run --release -p kvn-core --example bench
```

| Операция | ns/op | Итераций |
|---|---|---|
| parse vless reality+xhttp | 4953 | 1000 |
| parse vless tls+ws | 3191 | 1000 |
| parse shadowsocks-2022 | 1709 | 1000 |
| build xray client config | 15629 | 1000 |
| parse stats json (4 счётчика) | 924 | 1000 |
| state machine connect→ready→ok | 116 | 10 000 |

Замечания:

- Строка «build xray client config» включает сериализацию конфига в JSON
  и `.to_string()` — то есть это стоимость полного цикла генерации.
- **Парсинг stats json в примере — локальная копия парсера** (self-contained
  shim), эквивалентная `kvn_engine::stats::parse_stats_json`. Реальная
  реализация живёт в `kvn-engine` и покрыта юнит-тестами; цифра 924 ns/op
  характеризует алгоритм, а не именно крейтовую функцию.
- Машина состояний — чистый in-memory переход (без I/O): цикл
  `ConnectRequested → EngineReady → HealthCheckPassed`.

## Десктопное приложение

Замеры: `scripts/benchmark-app.py`, 3 прогона по релизному бинарнику.
Перед каждым прогоном каталог данных удаляется, поэтому каждый прогон —
чистый старт с нулевым состоянием.

### Время старта

Две метрики:

- **бэкенд готов** — от запуска процесса до появления каталога данных
  (настройки, каталоги `bin/`/`runtime/`/`logs/` созданы, контроллер
  запущен);
- **UI готов** — от запуска процесса до строки `ui boot finished` в
  `logs/kvn.log`: webview загрузил встроенный фронтенд, JS выполнился,
  IPC работает (это сквозная проверка, а не просто «окно появилось»).

| Прогон | Бэкенд готов | UI готов |
|---|---|---|
| 1 | 310 мс | 582 мс |
| 2 | 354 мс | 634 мс |
| 3 | 342 мс | 626 мс |
| **Медиана** | **342 мс** | **626 мс** |

Проверка production-бандла (`KVN.app/Contents/MacOS/kvn-desktop`) отдельно:
все этапы загрузки UI (`boot probe loaded` → `ui boot finished`) в журнале
на месте; CSP (`script-src 'self'`) встроенный фронтенд не ломает.

### Память в idle (RSS)

| Метрика | Значение |
|---|---|
| Медиана RSS | 98.5 MiB |
| Разброс по прогонам | 97.1–99.1 MiB |

Считается сумма RSS по дереву процессов (main process + его потомки)
через `ps`. **Ограничение:** подпроцессы WebKit на macOS не являются
дочерними процессами приложения, поэтому в замер не входят — реальное
суммарное потребление вместе с нативным рендерингом выше этой цифры.

### Завершение (teardown)

| Сценарий | Результат |
|---|---|
| `SIGTERM` | приложение завершается чисто (3/3 прогонов) |
| Процессы-сироты приложения после выхода | нет |

## Что не измерено

Честные границы текущих замеров:

- **Скорость трафика через реальный VPN** — требует удалённого сервера,
  в этом стенде не измерялась. (Интеграционные тесты проходят живой
  трафик через локальные Xray-процессы, но цифры loopback-стенда не
  репрезентативны для реальной сети — поэтому не приводятся.)
- **Время установления туннеля на реальном сервере** (от `connect` до
  `Connected`, и раздельно `wait_for_port` vs health-check) — тоже
  требует живого удалённого сервера.
- **Потребление ресурсов на Linux/Windows** — не проверено; цифры
  действительны только для macOS arm64.
- **Полный RSS приложения вместе с WebKit-хелперами** — см. ограничение
  выше.
- **Время до первого кадра окна** — измерялась готовность UI через
  журнал (см. выше), а не отрисовка первого кадра.

## Как воспроизвести

Микробенчмарки ядра:

```
cargo run --release -p kvn-core --example bench
```

Размеры фронтенда:

```
cd apps/desktop && pnpm build
```

Десктопное приложение (сначала прод-сборка, затем 3 прогона; флаг
`--keep-state` сохраняет каталог данных между прогонами):

```
pnpm tauri build           # либо сырой бинарник:
                           # cargo build --release -p kvn-desktop --features custom-protocol
python3 scripts/benchmark-app.py --runs 3
```
