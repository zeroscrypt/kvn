# Поддержка платформ и честный статус проверки

Термины, чтобы не было двусмысленности:

- **Протестировано** — есть реальный прогон на этой платформе: юнит- и
  интеграционные тесты с живым Xray, запуск приложения, замеры.
- **Собирается в CI** — воркфлоу на каждый PR собирает приложение и гоняет
  тесты (включая интеграционные с живым Xray) на этой платформе; живой
  прогон туннеля руками на реальной сессии при этом может быть не
  выполнен.
- **Не проверено** — ничего из перечисленного.

## Матрица платформ

| Платформа | Статус | Что именно проверено | Ограничения |
|---|---|---|---|
| **macOS arm64 (Apple Silicon)** | ✅ Протестировано | 62+16+17 юнит-тестов, 4 интеграционных теста с живым Xray v26.3.27 (VLESS+REALITY TCP/WS/XHTTP), smoke-запуск release-сборки и .app-бандла, окно и UI, меню-бар (трей: значок и меню), холодный старт и RSS (см. BENCHMARKS.md) | TUN-режим не реализован |
| macOS x86_64 | ⚠️ Не проверено | Код собирается, digest движка закреплён; живой прогон — нет | — |
| **Linux x86_64** | ⚠️ Собирается в CI | Воркфлоу собирает и тестирует крейты и приложение при каждом PR; системный прокси — только GNOME (gsettings), best-effort; меню-бар (AppIndicator) компилируется | Живой прогон туннеля и трея не выполнялся; не GNOME-среды (KDE, i3 и др.) — прокси не меняется |
| Linux arm64 | ⚠️ Не проверено | Присутствует digest движка; CI для сборки релиза этой архитектуры не настроен | — |
| **Windows x86_64** | ⚠️ Собирается в CI | Воркфлоу собирает крейты и приложение, гоняет юнит-тесты; digest движка закреплён; меню-бар компилируется | Живой прогон не выполнялся; системный прокси **не реализован** (явная ошибка); WebView2 обязателен (стандартно в Windows 11) |
| Android / iOS | 🕐 Не начато | — | По плану после стабилизации десктопа |

## Движки по платформам

Пиннится один релиз `Xray-core v26.3.27`: единственный источник —
`core/xray.json` (релиз, архивы, SHA-256, target-триплеты), он встраивается
в бинарь на этапе компиляции, а скрипты и CI читают тот же файл (см. также
`docs/RESEARCH.md`). Релизные сборки несут движок **в комплекте**
(sidecar, ADR 0005) — первый запуск не требует сети.

| Платформа приложения | Архив движка | Sidecar в релизной сборке | Распаковка проверена вживую |
|---|---|---|---|
| macOS arm64 | `Xray-macos-arm64-v8a.zip` | ✅ | ✅ (скачан и запущен локально) |
| macOS x86_64 | `Xray-macos-64.zip` | ✅ | — |
| Linux x86_64 | `Xray-linux-64.zip` | ✅ | — |
| Linux arm64 | `Xray-linux-arm64-v8a.zip` | ⚠️ (вне матрицы релиза) | — |
| Windows x86_64 | `Xray-windows-64.zip` | ✅ | — |

Движок можно переустановить из UI (Settings → Engine → Install — всегда
закреплённый релиз, digest проверяется) и указать свой бинарник: он должен
пройти `xray version`, дальше KVN с ним работу не ограничивает. Кнопка
«Проверить обновления» сверяет пин с последним релизом на GitHub
информационно (ADR 0005).

## Что нужно, чтобы закрыть «не проверено»

1. **macOS x86_64** — прогон `cargo test -p kvn-engine` с `XRAY_BIN` на
   Intel-Mac или Rosetta-эмуляции и запуск приложения.
2. **Linux x86_64/arm64** — запуск приложения в живой сессии (X11 и
   Wayland), прогон интеграционных тестов; проверить gsettings-прокси в
   GNOME и значок в меню-баре (AppIndicator).
3. **Windows x86_64** — запуск приложения, прогон интеграционных тестов;
   проверить значок в трее; после этого можно браться за системный прокси
   (см. ADR 0004).
4. **CI** — расширить матрицу (Linux arm64 `cross`/`aarch64` runner), это
   даст хотя бы «Собирается (CI)» без живой проверки.

Отчёты о прогонах приветствуются в issues — с версией ОС и выводом
Diagnostics export (он не содержит секретов).
