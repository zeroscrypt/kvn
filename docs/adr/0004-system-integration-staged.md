# ADR 0004. Интеграция с системой: системный прокси поэтапно, TUN отложен

Статус: принято (2026-10), Windows-часть — план.

## Контекст

«Полноценный VPN-клиент» обычно означает перехват всего трафика. Варианты:

1. **Системный прокси** (HTTP/HTTPS → локальный порт туннеля);
2. **TUN-интерфейс** (весь трафик через виртуальный адаптер, включая
   приложения, игнорирующие прокси);
3. Ничего — только локальные SOCKS/HTTP порты, пользователь настраивает сам.

TUN на всех трёх платформах требует привилегированного компонента
(utun/фильтры драйверов/WinTUN), подписи и отдельного аудита — это
существенный кусок работы, который легко сделать небезопасно.

## Решение

Поэтапно, в порядке платформ:

1. **Сейчас**: локальные SOCKS5 + HTTP порты (всегда, на всех платформах)
   и **опциональный системный прокси**:
   - macOS: `networksetup` — выбор основного сетевого сервиса (по
     `route … get default` → интерфейс → имя сервиса), сохранение прежних
     значений, восстановление при отключении и **после аварийного
     завершения** (файл-бэкап на диске восстанавливается при старте);
   - Linux: GNOME `gsettings` — best-effort, только GNOME-сессии
     (честно помечено в UI и документации);
   - Windows: не реализовано — команда возвращает понятную ошибку.
2. **Позже**: TUN-режим отдельным ADR с полным разбором привилегий
   (отдельный хелпер-процесс, принцип наименьших прав, откат при падении).

Важные правила, уже действующие:

- Системный прокси включается **только когда туннель реально поднят и
  проверен трафиком**; выключается при любом переходе из `Connected`.
- Ничего не меняется «в фоне»: автовключение — только по явной настройке
  «Set system proxy automatically while connected».
- Никаких прав root: `networksetup` для прокси-настроек их не требует.

## Последствия

+ Быстро приносит пользу там, где это безопасно (HTTP/HTTPS-трафик
  браузеров уважает системный прокси).
+ Отсутствие скрытых драйверов/TUN = меньшая поверхность атаки.
− Приложения, игнорирующие системный прокси, требуют ручной настройки
  SOCKS-порта (в UI он всегда показан).
− Windows-пользователь пока без системного прокси (порты работают) —
  это отражено в `docs/PLATFORM_SUPPORT.md` как «не реализовано».
